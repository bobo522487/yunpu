# Yunpu Constitution

## Core Principles

这些原则约束行为，不构成一套需要编号索引或文档校验才能合并的治理机器。
要改这些原则，必须在 `docs/decisions/` 写明放弃了什么。

### 非法状态存不进去

能由数据库拒绝的组合，必须由数据库拒绝。包括唯一性、条件唯一、互斥、取值范围、引用完整性、删除时的级联或限制，以及触发器能够拒绝的跨行规则。
应用层不得把这些规则散落成靠人记得的判断。

### 同一事实只有一处权威

- 表、列、约束、触发器、行级策略：已执行的迁移，以及同一次变更里与之同名的 Drizzle schema。
- 对外请求与响应形状：`apps/api/src/app.ts` 导出的 `AppType`。
- 失败码与 HTTP 状态：`packages/shared/src/errors.ts` 的 `ERROR_STATUS`，以及 `apps/api/src/lib/errors.ts` 的 `mapDatabaseError`。按 SQLSTATE 和约束名映射，不解析错误文本。

不维护编号族、追溯矩阵、软约束登记表或外键例外白名单。

### 失败对调用方可见

错误要么是明确的失败，要么向上抛出。禁止静默吞掉后当成成功。

### 租户数据不串

租户隔离由数据库行级策略执行。应用只在 `withTenantTransaction` 里设置事务局部的 `app.user_id`。
不在这次事务里的连接读不到也写不了租户表。连接归还后身份消失。
健康检查、认证库和迁移命令是仅有的三个例外，写在 `docs/boundaries.md`。

### 简单胜过聪明

能用一张表说清的事，不建第二张表。能用数据库约束说清的事，不建抽象层。
不引入依赖注入容器。不为还没出现的表预建索引或登记软约束。

### 删除是物理删除

数据删除即物理删除。归档是状态，不是删除的替代。

## 合并条件

合并取决于真实 PostgreSQL 上的测试和代码检查。
文档校验、编号完整性、两次散文门禁、复杂度例外账本都不是合并条件。

## 版本

- MAJOR：删除或重新定义上述原则。
- MINOR：新增原则。
- PATCH：措辞澄清。

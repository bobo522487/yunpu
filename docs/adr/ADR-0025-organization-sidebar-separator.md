# ADR-0025: 组织侧栏分隔线只在贴边展开时独占绘制，并记住宽度

2026-11-28，组织空间的**组织侧栏**右缘看起来能拖，实际只是 shadcn `SidebarRail` 的单击折叠。决定让它在与**内容区**直接相接且展开时，按 [ADR-0024](ADR-0024-business-sidebar-separator-ownership.md) 成为真正的**组织侧栏分隔线**，并单独记住宽度。

## Decision

1. **贴边且展开时，分隔线只负责调宽，并独占那条 1px 边。** 桌面端、布局外观为贴边（`sidebar`）且侧栏展开时，用与业务侧栏相同的分隔件：8px 热区、线钉在左缘、整数像素、静止 `--border`、悬停/聚焦/拖拽 `--primary` 且不加粗、`role="separator"`、左右键 16px、Home/End 到 220/380。单击这条线不再折叠。此状态下组织侧栏自己不画右边框。
2. **分隔线不在的时候，边框按状态补回或取消。** 收成图标时没有分隔线，由组织侧栏自己画右边框。完全收起时侧栏在屏幕外，不画。窄屏仍是抽屉，没有分隔线。
3. **只有贴边能拖。** 内嵌与浮动保持现有留白或卡片边，宽度固定 256px，并去掉会误导的可拖拽光标。
4. **展开宽度默认 256px，范围 220–380px，越界钳制，并与开合一起记住。** 记在与 `sidebar_state` 相同的 7 天 cookie 中，不按组织分开。只在贴边且展开时使用；切到内嵌或浮动不擦掉这份记忆，切回贴边后恢复。布局重置在恢复默认开合的同时把宽度收回 256px 并清掉记忆。折叠仍用 Ctrl/Cmd+B、布局设置和桌面页头按钮；页头按钮在三种外观下都有。
5. **与业务侧栏的宽度互不影响。** 拖拽沿用现有鼠标按下拖动，拖动过程中不播宽度动画。

## Considered Options

- **分隔线单击仍然折叠**：否决。这条线的职责是调宽，折叠已有快捷键、布局设置和页头按钮。
- **内嵌和浮动也画线、也能拖**：否决。内嵌的边界是留白，浮动的边界是卡片自己的一圈边，再加一条线或留下可拖拽光标会重复「看起来能拖」的问题。
- **宽度像业务侧栏一样刷新后回到初始值**：否决。组织侧栏的开合已经记住，宽度跟它一起记住；业务侧栏宽度不记住是因为它从未被写入偏好，不是产品规则。
- **拖过下限就折叠**：否决。越界钳制，折叠不由拖拽触发。
- **收成图标时也由分隔线画边**：否决。分隔线此时不存在，图标列需要自己的右边框才不会和内容区贴死。

## Consequences

- 术语见 `docs/glossary.md` 的**组织侧栏**与**组织侧栏分隔线**。历史 ADR 里的「单主侧栏」「全局侧栏」不改写。
- 不修改业务侧栏分隔线的行为，也不把两处宽度合成一份。
- [ADR-0016](ADR-0016-project-workspace-three-pane-shell.md) 的路由边界不变：`/projects/$projectId/*` 仍是项目三栏，其余组织页面仍是组织侧栏。

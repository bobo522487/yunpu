# 开发与测试环境（Development & Test Environment）

> 本文件只描述业务行为、规则与验收契约，不包含 SQL、框架、内部类名等技术实现细节。关键业务规则未向需求方澄清前，不得自行猜测补全。本功能交付的是独立后端对外提供的 JSON API 运行环境；产品前端在独立仓库，不在本功能范围内。

## 1. Overview

本功能搭建项目的开发与测试环境，确保平台基础设施能力可在真实的平台边界上编写与检查。目标是为开发者和测试执行者提供两套互不共享数据的环境：一套供日常开发并保留数据，一套供自动检查并从空起点开始。每套环境同时只运行三项——应用、数据库、私有对象存储；只有三项全部就绪，环境才算可用。

- **使用场景**：新开发者在前置条件已备齐的机器上按唯一说明启动开发环境，让应用进程、数据库、私有对象存储三项就绪；测试执行者在开发环境仍运行时单独启动测试环境，让依赖数据规则与租户隔离的检查打在真实数据库上；使用者把选定环境恢复到已知起点。
- **非目标（Out of Scope）**：生产环境的部署、备份、恢复演练与停机迁移；具体业务检查用例的定义；缓存、消息队列、搜索引擎和第二套数据库；产品最终用户的登录；安装操作系统或把前置条件的下载时间计入启动预算；构建、托管或验证产品前端工程（前端在独立仓库）。

## 2. User Stories

- **US-01**：作为新加入的开发者，我希望按一条路径一次拉起可工作的开发环境，以便无需他人协助就能看到三项就绪并开始调用后端 JSON API（Priority: P1）。
- **US-02**：作为测试执行者，我希望启动一套与开发环境隔离的测试环境，以便租户隔离与数据规则的检查打在真实数据库上且私有对象无法越权读取（Priority: P2）。
- **US-03**：作为开发者或测试执行者，我希望把选定环境恢复到已知起点，以便一次失败的检查或脏数据不会污染后续结果（Priority: P3）。

### US-01 验收场景

1. **Given** 机器已满足前置条件且无残留环境，**When** 按说明启动开发环境，**Then** 应用、数据库、私有对象存储三项都运行，就绪结果为可用。
2. **Given** 开发环境已就绪，**When** 查询就绪状态，**Then** 结果逐项给出应用、数据库、对象存储的可用状态并确认版本为产品要求的那一代，不含真实客户或家族资料。
3. **Given** 某一项前置条件缺失，**When** 执行启动，**Then** 启动失败并指出缺失项，就绪结果不得为可用。
4. **Given** 三项中有一项未启动，**When** 启动过程结束，**Then** 就绪结果逐项标明失败项，整体不得为可用。
5. **Given** 开发环境曾就绪后某项停止，**When** 再次查看就绪结果，**Then** 该项被标为未就绪，整体不得为可用。
6. **Given** 开发环境已就绪，**When** 清点正在运行的基础设施，**Then** 只有应用、数据库、私有对象存储三项，无缓存、队列、搜索或第二套数据库。

### US-02 验收场景

1. **Given** 开发环境已有示例数据，**When** 测试环境启动并完成检查，**Then** 两环境的业务数据互不可见。
2. **Given** 测试环境已就绪，**When** 执行依赖数据规则或租户隔离的检查，**Then** 全部发生在该环境真实数据库上，没有一条因替身而通过。
3. **Given** 测试环境数据库代际与产品要求不一致，**When** 执行启动，**Then** 启动失败并说明代际不符，环境不得标为可用。
4. **Given** 测试环境中已通过应用存入对象，**When** 未出示本环境能力令牌就直接读取，**Then** 读取失败；出示正确令牌并经应用后可以读到，不要求产品登录。
5. **Given** 对象存在于某一环境，**When** 使用另一环境的令牌经应用读取，**Then** 读取失败。
6. **Given** 启动目标被标成生产或连接指向生产数据，**When** 启动任一环境，**Then** 启动被拒绝，生产数据不被读取或改写。
7. **Given** 测试环境刚启动、尚未装入检查数据，**When** 查看其中业务数据，**Then** 没有预置数据。

### US-03 验收场景

1. **Given** 开发环境中有本轮新建数据，**When** 恢复开发环境，**Then** 数据全部消失，回到空起点，两分钟内再次就绪。
2. **Given** 测试环境中有检查写入的数据，**When** 恢复测试环境，**Then** 数据全部消失，回到空起点，两分钟内再次就绪。
3. **Given** 两个环境同时运行，**When** 只恢复其中一个，**Then** 另一个的数据与就绪状态保持不变。
4. **Given** 上一轮环境未停止且仍占用资源，**When** 再次启动同一环境，**Then** 要么先干净接管并达到就绪，要么明确指出占用冲突；不得在半新半旧的数据上报告可用。
5. **Given** 恢复过程中仍有写入，**When** 恢复结束，**Then** 环境处于已知起点，不保留恢复期间的半成品数据。
6. **Given** 开发环境已写入可识别数据并已停止，**When** 再次启动，**Then** 数据仍在且达到就绪。
7. **Given** 测试环境已有检查写入的数据，**When** 再次启动测试环境，**Then** 数据不在，以空起点达到就绪。

## 3. Functional Requirements

> 每条需求使用唯一 ID 描述明确可验证的系统行为。

### FR-001：唯一的开发环境启动路径
- 系统必须提供唯一的开发环境启动路径。
- 启动结果只包含应用、数据库、私有对象存储这三项同时运行的基础设施。

### FR-002：开发与测试环境分离
- 系统必须提供与开发环境分离的测试环境。
- 两个环境的业务数据互不可见。

### FR-003：前置条件缺失要失败
- 前置条件缺失时启动必须失败并指出缺失的条件。
- 不得把环境标为可用。

### FR-004：逐项就绪判定
- 就绪结果必须分别给出应用、数据库、私有对象存储的状态。
- 只有三项都就绪时整体才可用。

### FR-005：数据库代际一致
- 两个环境中的数据库都必须是产品要求的那一代。
- 代际不符时启动失败。

### FR-006：检查打在真实数据库上
- 依赖数据规则或租户隔离的自动检查必须打在该环境的真实数据库上。
- 不得因替身或跳过而记为通过。

### FR-007：每环境一把能力令牌
- 每个环境必须有一把不能用于另一环境的能力令牌；绕过应用的直接读取必须失败。
- 经应用读取时只有出示本环境正确令牌才算授权并返回对象；缺少令牌、令牌错误或使用另一环境令牌都必须失败。
- 本功能不实现产品登录。

### FR-008：拒绝生产目标
- 开发环境与测试环境都必须拒绝指向生产数据的启动目标。
- 不得读取或改写生产数据。

### FR-009：恢复到已知起点
- 使用者必须能把选定环境恢复到已知起点：清空本环境上一轮数据后重新就绪。
- 上一轮数据不再存在。

### FR-010：恢复的隔离性
- 恢复一个环境不得改变另一个环境或生产数据。

### FR-011：空起点与无真实数据预置
- 测试环境在具体检查装入自己的数据之前必须为空。
- 两个环境的初始数据都不得来自真实客户或真实家族资料。
- 本功能不构建、不托管产品前端页面，前端及其示例页面在独立仓库。

### FR-012：停止与重启的数据语义
- 停止环境必须释放它占用的端口与进程。
- 停止开发环境后再次启动，上一轮数据仍在，不得因残留占用失败，也不得接上另一套环境的数据。
- 启动测试环境时必须先清除上一轮检查留下的数据，再以空起点标为可用。

### FR-013：就绪后的组件失效
- 环境就绪之后若任一组件停止，下一次就绪查看必须把该组件标为未就绪，且整体不得为可用。

### FR-014：三项组件预算
- 启动结果不得包含缓存、消息队列、搜索引擎或第二套数据库。
- 出现其中任何一项，环境不得标为可用。

## 4. Business Rules

- **澄清（2026-11-14）**：环境停掉再启动后，开发环境保留数据、只有恢复才清空；测试环境每次启动都先回到空起点。
- **澄清（2026-11-14）**：经应用读取私有对象时，每环境一把能力令牌，带对令牌才算授权；不实现产品登录。
- 使用者是开发者与测试执行者，不是修谱产品的最终用户；成功以他们能否独立启动、检查和恢复环境衡量。
- 本仓库是独立后端，对外只提供 JSON API；产品前端在独立仓库，不随本环境的启动交付或验证。
- 平台同时运行的基础设施只有应用、数据库、私有对象存储三项；缓存、消息队列、搜索引擎和第二套数据库不在范围内。
- 「产品要求的数据库代际」指产品数据规则所依赖的那一代；本功能不改变代际选择，只要求环境与该选择一致。
- 开发环境与测试环境各限一套，绑定在同一台工作机器或同一次测试运行；第二套开发环境启动时应失败而不是共用数据。
- 机器需先满足前置条件；本功能不安装操作系统，也不把下载前置条件的等待算进启动预算。
- **澄清（2026-11-25）**：容器运行时前置条件满足于 Docker 或 Podman 任一可用；两者都不可用时启动失败并指出缺失项。
- 环境初始不预置真实客户或家族资料；检查所需数据由检查自身装入，不复制生产库。
- 具体业务检查用例不在本功能内定义；本功能只保证有一套隔离、真实的数据库和私有存储，且空起点不被预置数据污染。
- 对象是否可公开读取以「未授权直接读取必须失败」为验收，不另建公开访问通道。
- 恢复期间若有写入，以恢复完成后的已知起点为准，不保留半成品，以保证下一次检查起点可重复。
- 停止开发环境只释放占用并保留数据；清空开发环境必须走恢复；测试环境每次启动都先回到空起点。
- 授权指本环境的能力令牌，不是产品用户登录；每环境一把，不能互换。

## 5. Exception Handling

- 前置条件缺失或数据库代际不符：启动以非零退出并指出缺失项或代际不符，环境不得标为可用，端口上没有新服务。
- 启动目标指向生产或库名被配成生产目标：启动被拒绝（非零退出），生产数据无读取、无改写。
- 三项中任一未就绪或随后停止：就绪结果整体不可用（HTTP 503，失败项带 `reason`），不把 `ok` 设为真。
- 缺少令牌、令牌错误或令牌属于另一环境：经应用的读取/写入返回 `401 UNAUTHORIZED`，对象不被写入、不返回内容。
- 对象键不存在或非法：经应用读取返回 `404 NOT_FOUND` 或 `400 VALIDATION`。
- 请求正文超过本功能证明上限：返回 `413`，对象不写入。
- 绕过应用、不带存储根凭证直接请求对象地址：响应状态不是 200，正文不是对象内容。
- 端口被其他项目占用：启动进入失败并以非零退出，指出端口；不接管那套数据，不把两边数据接在一起后报告可用。
- 对象存储被配成无需授权即可读取：启动失败或就绪结果为不可用。
- 检查数据出现真实客户、真实家族资料：该环境不得标为可用。
- 配置错误（环境名非开发/测试、库名不成对、令牌为空）：进程打印失败字段并以非零退出，端口上没有服务。

## 6. Acceptance Criteria

- [x] **AC-001**（对应 `FR-001`、`FR-014`）：前置条件已备齐时新开发者第一次启动开发环境，15 分钟内整体可用且无需求助，连续三次干净机器尝试全部成功；任一时刻运行的基础设施组件数为 3，组件数不为 3 的启动不被判为可用。
- [x] **AC-002**（对应 `FR-004`、`FR-013`）：就绪查看在 10 秒内返回三项各自状态；任一项未就绪时整体可用判定为否，准确率 100%。
- [x] **AC-003**（对应 `FR-005`、`FR-006`）：依赖数据规则或租户隔离的检查 100% 在测试环境真实数据库执行，因替身或跳过而记为通过的条数为 0；代际不符的启动 100% 失败。
- [x] **AC-004**（对应 `FR-007`）：绕过应用的直接读取以及经应用但令牌缺失、错误或属于另一环境的读取 100% 失败；出示本环境正确令牌并经应用的读取能取回原对象。
- [x] **AC-005**（对应 `FR-002`、`FR-008`）：开发环境、测试环境、生产数据三者之间任一对的业务数据可见记录数为 0；指向生产的启动 100% 被拒绝。
- [x] **AC-006**（对应 `FR-009`、`FR-010`）：选定环境的恢复在 2 分钟内完成；恢复后上一轮数据查找结果为 0 条，另一环境数据条数不变。
- [x] **AC-007**（对应 `FR-011`、`FR-012`、`FR-014`）：测试环境未装入检查数据前为空，两个环境初始均无真实家族资料；停止开发环境后再次启动原数据仍在，再次启动测试环境后上一轮检查数据为 0 条。

# Feature Specification: 开发与测试环境

**Feature Branch**: `001-dev-test-environment`

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "搭建项目开发测试环境，确保平台基础设施能力"

## Clarifications

### Session 2026-11-14

- Q: 把环境停掉再启动之后，上一轮写入的数据应该怎样处理？ → A: 开发环境保留数据，只有恢复才清空；测试环境每次启动都先回到空起点。
- Q: 经应用读取私有对象时，怎样才算已经获得授权？ → A: 每个环境一把能力令牌。带对令牌才算授权，不实现产品登录。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一次拉起可工作的开发环境 (Priority: P1)

新加入的开发者在前置条件已经备齐的机器上，按唯一的说明启动开发环境。环境只包含平台允许同时运行的三项：应用、数据库、私有对象存储。启动结束后，开发者能看到每一项是否就绪；只有三项全部就绪时，环境才算可用。开发者打开产品，能进入一份合成的示例工作区，并确认私有文件只能经过应用访问。

**Why this priority**: 没有可重复启动的开发环境，后续功能无法在真实的平台边界上编写和检查。当前依赖数据库真实行为的核对无法执行，就是因为这一步缺失。

**Independent Test**: 在一台只满足前置条件、没有残留环境的机器上执行启动说明，不借助他人协助。完成后读取就绪结果，打开产品并看到示例工作区，再尝试绕过应用直接读取一个私有文件。

**Acceptance Scenarios**:

1. **Given** 机器已满足文档列出的前置条件，且不存在上一轮留下的环境，**When** 开发者按说明启动开发环境，**Then** 应用、数据库、私有对象存储三项都处于运行状态，就绪结果为「可用」。
2. **Given** 开发环境已就绪，**When** 开发者打开产品，**Then** 能进入一份合成示例工作区，且其中不包含任何真实客户或家族资料。
3. **Given** 某一项前置条件缺失，**When** 开发者执行启动，**Then** 启动失败，并指出缺失的是哪一项；就绪结果不得为「可用」。
4. **Given** 三项中有一项未能启动，**When** 启动过程结束，**Then** 就绪结果逐项标明失败的那一项，整体不得为「可用」。
5. **Given** 开发环境曾经就绪，之后数据库或对象存储停止，**When** 开发者再次查看就绪结果，**Then** 停止的那一项被标为未就绪，整体不得为「可用」。
6. **Given** 开发环境已就绪，**When** 清点正在运行的基础设施，**Then** 只有应用、数据库、私有对象存储三项，没有缓存、队列、搜索或第二套数据库。

### User Story 2 - 测试环境证明基础设施能力 (Priority: P2)

测试执行者启动一套与开发环境分开的测试环境。依赖数据库规则和租户隔离的自动检查打在这套真实数据库上，而不是打在替身或跳过检查上。私有对象存储同样拒绝未经应用授权的直接读取。测试环境不包含开发环境的示例数据，也不接触生产数据。

**Why this priority**: 平台的隔离和数据规则只有在真实数据库上才算数。测试环境若用替身放行，基础设施能力等于没有被证明。

**Independent Test**: 在开发环境保持运行且已写入示例数据的情况下，单独启动测试环境并执行一组基础设施检查：租户隔离、数据库代际、私有存储拒绝未授权读取、以及测试环境看不到开发环境的数据。

**Acceptance Scenarios**:

1. **Given** 开发环境已有示例数据，**When** 测试环境启动并完成检查，**Then** 测试环境中查不到开发环境的任何数据，开发环境也查不到测试环境写入的数据。
2. **Given** 测试环境已就绪，**When** 执行依赖数据库规则或租户隔离的检查，**Then** 这些检查全部发生在该环境的真实数据库上，没有一条因为使用替身而通过。
3. **Given** 测试环境的数据库代际与产品要求不一致，**When** 执行启动，**Then** 启动失败并说明代际不符，环境不得标为可用。
4. **Given** 测试环境中已通过应用存入一个对象，**When** 访问者未出示该环境的能力令牌就直接读取，**Then** 读取失败；出示该环境的正确令牌并经过应用后可以读到该对象。不要求产品登录。
5. **Given** 对象存在于某一环境，**When** 使用另一环境的能力令牌经应用读取，**Then** 读取失败。
6. **Given** 启动目标被标成生产，或连接指向生产数据，**When** 执行开发环境或测试环境的启动，**Then** 启动被拒绝，生产数据不被读取或改写。
7. **Given** 测试环境刚启动、尚未运行具体检查，**When** 查看其中的业务数据，**Then** 其中没有预置的示例工作区。

---

### User Story 3 - 把环境恢复到已知起点 (Priority: P3)

开发者或测试执行者把选定的环境恢复到已知起点。上一轮写入的数据不再存在。恢复开发环境不会影响测试环境，恢复测试环境也不会影响开发环境。停止开发环境只释放占用，数据仍在；再次启动不会因为占用残留而失败。测试环境每次启动都先清空上一轮数据，再进入空起点。

**Why this priority**: 环境不能复位时，一次失败的检查或一份脏数据会污染后续所有结果，基础设施是否真正可用就无法重复证明。

**Independent Test**: 在两个环境都已就绪并各自写入可识别的数据后，只恢复其中一个，再分别查找两边的数据，并在停止后立即再次启动。

**Acceptance Scenarios**:

1. **Given** 开发环境中已有本轮新建的数据，**When** 开发者恢复开发环境，**Then** 这些数据全部消失，环境回到含合成示例工作区的起点，并在两分钟内再次就绪。
2. **Given** 测试环境中已有检查写入的数据，**When** 测试执行者恢复测试环境，**Then** 这些数据全部消失，环境回到不含示例工作区的空起点，并在两分钟内再次就绪。
3. **Given** 两个环境同时在运行，**When** 只恢复其中一个，**Then** 另一个环境的数据与就绪状态保持不变。
4. **Given** 上一轮环境未停止并仍占用资源，**When** 再次启动同一环境，**Then** 要么先干净地接管并达到就绪，要么明确指出占用冲突；不得在半新半旧的数据上报告可用。
5. **Given** 恢复过程中仍有写入进入该环境，**When** 恢复结束，**Then** 环境处于已知起点，不保留恢复期间写入的半成品数据。
6. **Given** 开发环境已写入可识别数据并已停止，**When** 再次启动开发环境，**Then** 这些数据仍在，且环境达到就绪。
7. **Given** 测试环境已有检查写入的数据，**When** 再次启动测试环境，**Then** 这些数据不在，环境以空起点达到就绪。

### Edge Cases

- 前置条件缺失时，启动指出缺失项并失败，不留下被标为可用的半套环境。
- 应用已就绪但数据库或对象存储未就绪时，整体就绪结果为不可用，并标明失败项。
- 数据库代际低于或高于产品要求时，启动失败，不降级继续。
- 对象存储被配成无需授权即可读取时，启动失败或就绪结果为不可用。
- 启动目标指向生产数据时，启动被拒绝，生产数据无读取、无改写。
- 开发环境仍被占用时再次启动：要么接管同一套数据并达到就绪，要么指出占用冲突；不得混入另一套数据后报告可用。
- 停止开发环境后再启动：上一轮写入的数据仍在。
- 恢复某一环境时，另一环境正在运行：只改变被恢复的那一个。
- 检查中途中断后再次启动测试环境：启动先清除残留，空起点中看不到中断留下的数据。
- 同一台机器上试图再开第二套开发环境：启动失败并说明已有一套，不与现有环境共用数据。
- 示例数据或检查数据出现真实客户、真实家族资料：该环境不得标为可用。
- 缺少令牌、令牌错误，或使用另一环境的令牌经应用读取：读取失败，不返回对象内容。本功能不提供产品登录。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供唯一的开发环境启动路径，启动结果只包含应用、数据库、私有对象存储这三项同时运行的基础设施。
- **FR-002**: 系统必须提供与开发环境分离的测试环境；两个环境的业务数据互不可见。
- **FR-003**: 前置条件缺失时，启动必须失败，并指出缺失的条件；不得把环境标为可用。
- **FR-004**: 就绪结果必须分别给出应用、数据库、私有对象存储的状态；只有三项都就绪时，整体才为可用。
- **FR-005**: 两个环境中的数据库都必须是产品要求的那一代；代际不符时启动失败。
- **FR-006**: 依赖数据规则或租户隔离的自动检查必须打在该环境的真实数据库上，不得因替身或跳过而记为通过。
- **FR-007**: 每个环境必须有一把不能用于另一环境的能力令牌。绕过应用的直接读取必须失败。经应用读取时，只有出示本环境的正确令牌才算授权并返回对象；缺少令牌、令牌错误或使用另一环境的令牌都必须失败。本功能不实现产品登录。
- **FR-008**: 开发环境与测试环境都必须拒绝指向生产数据的启动目标，且不得读取或改写生产数据。
- **FR-009**: 使用者必须能把选定环境恢复到已知起点：开发环境回到含合成示例工作区的起点，测试环境回到不含示例数据的空起点，上一轮数据不再存在。
- **FR-010**: 恢复一个环境不得改变另一个环境或生产数据。
- **FR-011**: 开发环境就绪后必须带有一份合成示例工作区，足以打开产品并看到非空内容；该数据不得来自真实客户或真实家族。测试环境在具体检查装入自己的数据之前必须为空。
- **FR-012**: 停止环境必须释放它占用的端口与进程。停止开发环境后再次启动，上一轮写入的数据仍在，且不得因为残留占用而失败，也不得接上另一套环境的数据。启动测试环境时必须先清除上一轮检查留下的数据，再以空起点标为可用。
- **FR-013**: 环境就绪之后若任一组件停止，下一次就绪查看必须把该组件标为未就绪，且整体不得为可用。
- **FR-014**: 启动结果不得包含缓存、消息队列、搜索引擎或第二套数据库。出现其中任何一项，环境不得标为可用。

### Key Entities *(include if feature involves data)*

- **开发环境**: 供开发者日常使用的一套运行实例。含应用、符合代际要求的数据库、私有对象存储，以及一份合成示例工作区。与测试环境和生产数据隔离。
- **测试环境**: 供自动检查使用的一套运行实例。组件与开发环境相同，每次启动都先回到不含示例工作区和上一轮检查数据的空起点。检查写入的数据只存在于本环境，可恢复到空起点。
- **应用**: 使用者打开产品时所接触的那一项。开发环境通过它进入示例工作区。对象的授权读取经过它，并只接受本环境的能力令牌。
- **数据库**: 保存业务数据并强制执行数据规则与租户隔离的那一项。代际必须与产品要求一致，否则环境不可用。
- **能力令牌**: 每个环境一把。出示本环境的正确令牌并经过应用，才算获得授权。两套环境的令牌不能互换。不是产品登录会话。
- **私有对象存储**: 保存媒体对象的那一项。对象不能被未授权的直接读取取得。
- **就绪结果**: 对三项组件各自状态和整体是否可用的一次判定。任一项未就绪时，整体不可用。
- **示例工作区**: 只存在于开发环境起点中的合成内容，用于确认产品可被打开。不是生产数据，也不是测试夹具。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 前置条件已备齐时，新开发者第一次按说明启动开发环境，15 分钟内到达整体可用，且不需要向他人求助。连续三次在干净机器上的尝试全部成功。
- **SC-002**: 就绪查看在 10 秒内返回三项组件的各自状态。三项之中任一未就绪时，整体可用的判定为否，准确率 100%。
- **SC-003**: 依赖数据规则或租户隔离的自动检查，100% 在测试环境的真实数据库上执行；因替身或跳过而记为通过的条数为 0。
- **SC-004**: 绕过应用的直接读取，以及经应用但令牌缺失、错误或属于另一环境的读取，100% 失败。出示本环境正确令牌并经应用的读取能够取回原对象。
- **SC-005**: 开发环境、测试环境、生产数据三者之间，任一对的业务数据可见记录数为 0。指向生产的启动 100% 被拒绝。
- **SC-006**: 选定环境的恢复在 2 分钟内完成；恢复后查找上一轮数据的结果为 0 条，另一环境的数据条数保持不变。
- **SC-007**: 任一环境运行时，基础设施组件数为 3。组件数不为 3 的启动不被判定为可用。
- **SC-008**: 停止开发环境后再次启动，上一轮可识别数据仍可找到；再次启动测试环境后，上一轮检查数据为 0 条。

## Assumptions

- 本功能的使用者是开发者和测试执行者，不是修谱产品的最终用户。成功与否以他们能否独立启动、检查和恢复环境来衡量。
- 平台同时运行的基础设施只有三项：应用、数据库、私有对象存储。缓存、消息队列、搜索引擎和第二套数据库不在本功能内引入。
- 「产品要求的数据库代际」指产品数据规则所依赖的那一代数据库。本功能不改变代际选择，只要求环境与该选择一致。
- 开发环境与测试环境各限一套，绑定在同一台工作机器或同一次测试运行上。第二套开发环境不在范围内，启动时应失败而不是共用数据。
- 机器需先满足说明中列出的前置条件。本功能不负责安装操作系统，也不把下载前置条件的等待时间算进 15 分钟。
- 示例工作区是合成数据，规模只需要让开发者打开产品后看到非空内容。不复制生产库，不使用真实家族资料。
- 测试环境的具体业务检查用例不在本功能内定义。本功能只保证这些检查有一套隔离的、真实的数据库和私有存储可用，并且空起点不被预置数据污染。
- 生产环境的部署、备份、恢复演练和停机迁移不在本功能内。本功能只保证开发和测试启动不会碰到生产数据。
- 对象是否允许公开读取以「未授权直接读取必须失败」为验收，不另建公开访问通道。
- 恢复期间若仍有写入，以恢复完成后的已知起点为准；不保留半成品。这是为了让下一次检查的起点可重复。
- 停止开发环境只释放占用并保留数据；清空开发环境必须走恢复。测试环境每次启动都先回到空起点。
- 授权指本环境的能力令牌，不是修谱产品的用户登录。每个环境一把，不能互换。

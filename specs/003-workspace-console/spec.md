# Feature Specification: 工作台控制台（首页/项目/成员/设置）

**Feature Branch**: `003-workspace-console`

**Created**: 2026-11-15

**Status**: Draft

**Input**: User description: "工作台控制台功能；首页/项目/成员/设置 等等；"

**基线与引用**: 本批次只引用 `docs/` 与既有 spec 的结论，不复制表格。组织、成员、邀请与默认组织的规则见 [functional.md](../../docs/requirements/functional.md)（`FR-ORG-01`~`03`、`FR-TEN-01`~`03`）、[user-stories.md](../../docs/requirements/user-stories.md)（`US-007`、`US-008`）与 [spec 002](../002-user-auth-default-org/spec.md)（注册、登录、默认组织、引导状态）；项目生命周期与端点形状见 [endpoints.md](../../docs/architecture/api/endpoints.md) §2.2、§2.3。本规格只定义「登录后进入的工作台控制台这一层界面的行为与验收」，不重新定义组织、成员、邀请、项目的内部规则。

## 术语

- **工作台（控制台）**：用户登录后承载日常操作的主界面层，由首页、项目、成员、设置四个主页面组成，始终处于某一个当前组织的上下文中。
- **当前组织**：控制台此刻所处的组织。默认取账号的默认组织（见 spec 002），可在控制台内切换。
- **引导状态**：账号不属于任何可用组织时的状态（见 spec 002）。此时不展示四个主页面，只展示创建组织与接受邀请的入口。
- **首页**：进入控制台的落地页，回答「我现在管着什么、最近能做什么」。
- **项目页**：当前组织下项目（一份谱的数据边界）的列表与增删改入口。
- **成员页**：当前组织的成员名单、角色调整、邀请管理与所有权转移入口。
- **设置页**：当前组织的基础设置（改名、归档）与账号本人资料设置的入口。

## Clarifications

### Session 2026-11-15

- Q: 控制台是否需要组织切换能力，还是登录后固定在默认组织？ → A: 需要组织切换；切换即记住——切换后该组织成为账号的默认组织（与 spec 002 `FR-013`/`FR-014`、US4 场景 3 一致，2026-11-15 计划阶段修正，取代本行原答案「切换不改默认组织指针，除非显式设为默认」）。控制台不提供单独的「设为默认」操作。
- Q: 首页展示什么内容？ → A: 当前组织的概览：项目数与最近项目、成员数与待处理邀请数、快捷入口（新建项目、邀请成员）；不引入仪表盘图表、统计报表或跨组织聚合。
- Q: 设置页是否包含账号本人资料（显示名、密码）？ → A: 包含，设置页分「组织设置」与「账号设置」两个分区；组织设置按角色权限展示，账号设置只对本人生效。
- Q: 控制台内是否提供「创建新组织」入口？ → A: 提供，放在组织切换器旁（选项 A）；创建通过弹窗进行，弹窗内提供基于显示名/邮箱前缀的建议组织名称选项供用户直接选用，创建成功后自动切换为当前组织。
- Q: 归档当前组织后，控制台应把用户带到哪里？ → A: 自动切换到下一个可用组织；没有其他可用组织时进入引导状态（选项 A）。
- Q: 成员页创建邀请后，系统通过什么方式把邀请交给被邀请人？ → A: 创建成功后弹窗展示可复制的邀请链接，明文 token 只出现一次，之后只能从待处理邀请列表重新生成或查看状态（选项 A）。
- Q: 控制台页面在数据加载中和加载失败时应如何呈现？ → A: 加载中显示骨架屏占位；失败时页面内显示明确错误与「重试」按钮，不清空已有数据、不跳转登录（会话失效除外）（选项 A）。
- Q: 首页「最近项目」列表固定展示多少条，并如何查看全量？ → A: 固定展示最近 5 条，并提供「查看全部」入口跳转项目页（选项 A）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录后进入当前组织的首页 (Priority: P1)

一位修谱主事人登录后直接进入工作台首页。首页告诉他当前在哪个组织、这个组织下有多少项目、最近在做哪些项目、有多少成员、有没有待处理的邀请，并给出「新建项目」「邀请成员」两个快捷入口。他不需要翻遍菜单就能开始干活。

**Why this priority**: 首页是控制台的落脚点，也是「登录 → 可开始工作」这条链路的终点。没有它，用户登录后面对的是空白或散落的页面，spec 002 交付的默认组织在这里才真正兑现为可用的工作界面。

**Independent Test**: 用一个已有项目与成员的组织账号登录，确认落地页为该组织首页，且项目数、成员数、最近项目与实际数据一致；点击快捷入口能到达对应页面。

**Acceptance Scenarios**:

1. **Given** 用户已登录且有可用组织，**When** 进入控制台，**Then** 首页展示当前组织名称、项目数量、成员数量与最近项目列表，数据与该组织的实际内容一致。
2. **Given** 当前组织没有任何项目，**When** 查看首页，**Then** 明确展示「尚无项目」的空状态与新建项目入口，不显示错误，也不虚构示例项目。
3. **Given** 当前组织存在待处理邀请，**When** 查看首页，**Then** 显示待处理邀请数量并可跳转到成员页的邀请列表。
4. **Given** 用户点击「新建项目」或「邀请成员」，**When** 跳转完成，**Then** 分别落到项目页的创建入口与成员页的邀请入口，且仍处于同一组织上下文。
5. **Given** 用户属于多个组织，**When** 在首页切换当前组织，**Then** 首页内容整体替换为新组织的数据，不残留上一组织的项目或成员信息。

### User Story 2 - 项目页管理当前组织的谱项目 (Priority: P1)

一位修谱主事人在项目页看到当前组织下全部项目的列表，可以新建项目、打开某个项目继续工作、修改项目信息，也可以删除不再需要的项目。删除前会被告知后果，误删不会静默发生。

**Why this priority**: Project 是一份谱的数据边界，是所有业务数据的挂载点（`FR-ORG-01` 关联语义）。没有项目页，用户无法在控制台层建立任何业务数据的容器；它与首页共同构成控制台的最小可用切片。

**Independent Test**: 在项目页新建一个项目，确认它立即出现在列表中；修改名称后刷新确认保存；删除一个项目，确认经过确认步骤且列表中不再出现。

**Acceptance Scenarios**:

1. **Given** 当前组织已有若干项目，**When** 打开项目页，**Then** 列出本组织全部项目，且不含任何其他组织的项目。
2. **Given** 用户填写了合法的项目名称，**When** 提交新建，**Then** 项目创建成功并出现在列表中，创建者可立即进入该项目。
3. **Given** 项目名称为空或纯空白，**When** 提交新建，**Then** 创建被拒绝并明确提示要求，不产生空名称项目。
4. **Given** 用户修改项目名称或信息，**When** 提交保存，**Then** 修改生效并在刷新后保持；并发修改时后提交者收到明确的冲突提示，不静默覆盖。
5. **Given** 用户执行删除项目，**When** 确认删除，**Then** 项目及其列表条目消失；取消确认则不发生任何删除。
6. **Given** 当前用户只有只读角色，**When** 打开项目页，**Then** 可查看列表，但新建、修改、删除入口不可用或提交被拒绝，且提示明确。

### User Story 3 - 成员页查看与管理组织成员 (Priority: P2)

一位组织管理员在成员页看到当前组织的全部成员与角色，可以邀请新成员、调整成员角色、移除成员、撤销待处理的邀请，以及在需要时转移组织所有权。普通成员能看到名单，但做不了管理动作。

**Why this priority**: 成员管理是组织协作的前提，但它的价值依赖成员已经能通过邀请进入（spec 002 已交付兑换路径），因此排在首页与项目页之后。

**Independent Test**: 用管理员账号邀请一个邮箱并确认邀请出现在待处理列表；接受后该邮箱出现在成员列表；调整其角色、再移除，逐步确认权限变化与提示。

**Acceptance Scenarios**:

1. **Given** 当前组织有若干成员与待处理邀请，**When** 打开成员页，**Then** 分别展示成员名单（含角色、owner 标记）与待处理邀请列表，且不含其他组织的任何数据。
2. **Given** 管理员填写合法邮箱并选择角色，**When** 创建邀请，**Then** 邀请出现在待处理列表；同一组织同一邮箱已存在待处理邀请时，创建被拒绝并提示已存在。
3. **Given** 管理员撤销一条待处理邀请，**When** 确认撤销，**Then** 该邀请不再出现在待处理列表，且不能再被兑换。
4. **Given** 管理员修改某成员的角色，**When** 提交修改，**Then** 角色立即生效并在名单中反映；尝试修改 owner 的角色被拒绝。
5. **Given** 管理员移除某成员，**When** 确认移除，**Then** 该成员从名单消失，且其旧会话不再能看到本组织的任何数据；owner 不能被移除。
6. **Given** owner 发起所有权转移，**When** 选择一位已是成员的接手人并确认，**Then** 转移成功且仅一方生效（并发转移只成功一次）；非 owner 发起被拒绝。
7. **Given** 当前用户是只读成员，**When** 打开成员页，**Then** 可查看名单，但邀请、改角色、移除、转移所有权等管理入口不可用或提交被拒绝。
8. **Given** 管理员创建邀请成功，**When** 弹窗展示邀请链接，**Then** 链接可一键复制且明文只出现这一次；关闭弹窗后待处理列表只展示邮箱、角色与状态，不再展示明文链接。

### User Story 4 - 设置页管理组织与账号 (Priority: P2)

一位用户在设置页完成两类事：把当前组织改名、在不再使用时归档当前组织；以及修改自己的显示名与密码。组织设置按角色权限展示，账号设置只影响本人。

**Why this priority**: 设置是低频动作，但「组织改名/归档」是 `FR-ORG-02` 的界面兑现，缺少它组织生命周期在控制台层不闭环。

**Independent Test**: 在设置页修改组织名称并刷新确认保存；用管理员归档组织后确认该组织不再出现在可切换列表中；修改本人显示名后确认全控制台的展示随之更新。

**Acceptance Scenarios**:

1. **Given** 用户具有组织更新权限，**When** 在设置页修改组织名称并保存，**Then** 名称生效并在刷新后保持；空或纯空白名称被拒绝。
2. **Given** 用户具有归档权限，**When** 归档当前组织，**Then** 组织进入归档状态，数据保留，写入被拒绝，该组织不再作为可进入的当前组织，控制台自动切换到下一个可用组织（没有其他可用组织时进入引导状态）；界面对后果有明确说明。
3. **Given** 用户尝试归档组织但权限不足，**When** 提交，**Then** 操作被拒绝且提示明确，组织状态不变。
4. **Given** 用户在账号设置分区修改显示名，**When** 保存，**Then** 显示名对本人生效并在控制台各处一致展示；修改密码后需按既有规则重新验证。
5. **Given** 当前用户是只读成员，**When** 打开设置页的组织设置分区，**Then** 修改与归档入口不可用或提交被拒绝；账号设置分区仍可正常使用。

### User Story 5 - 组织切换与引导状态 (Priority: P2)

一位同时属于多个组织的用户，可以在控制台顶部切换当前组织，切换后四个页面的数据全部换成新组织的。当他不属于任何可用组织时，控制台不展示空壳页面，而是给出创建组织与接受邀请的入口。

**Why this priority**: 多组织是常态（spec 002 已交付默认组织选择），控制台必须承接它；引导状态则保证「被移出全部组织」的用户不会掉进空白页。

**Independent Test**: 加入两个组织后在控制台切换，确认首页/项目/成员/设置全部换数据；把账号移出全部组织后重新进入控制台，确认看到的是引导页而非空白或报错。

**Acceptance Scenarios**:

1. **Given** 用户属于多个组织，**When** 切换当前组织，**Then** 首页、项目、成员、设置四个页面的数据全部替换为新组织的数据，无跨组织残留。
2. **Given** 用户切换了当前组织，**When** 重新登录，**Then** 默认组织为上次切换到的组织（spec 002 `FR-014` 的「切换即记住」语义），不需要额外的「设为默认」操作。
3. **Given** 用户不属于任何可用组织，**When** 进入控制台，**Then** 展示引导状态：创建组织与接受邀请两个入口，不展示四个主页面，不静默创建组织。
4. **Given** 用户的当前组织被归档或用户被移出该组织，**When** 在另一个已打开的标签页继续操作，**Then** 写入被拒绝，并引导其切换组织或进入引导状态。
5. **Given** 用户没有查看某组织数据的权限，**When** 试图进入该组织的控制台，**Then** 得到「不存在或无权」的明确结果，不泄漏该组织数据的存在性。

---

### Edge Cases

- 当前组织恰好在切换过程中被归档：自动进入下一个可用组织，没有其他可用组织时进入引导状态，不落入已归档组织的页面。
- 组织内最后一个非 owner 成员被移除：owner 始终在成员名单中，不出现「空组织」。
- 转移所有权时接手人已不再是成员：转移被拒绝并明确提示，owner 不变。
- 同一邀请被两个浏览器同时撤销：只有一方成功，另一方收到明确错误，不产生「撤销成功但邀请仍在」的假象。
- 两个管理员同时修改同一成员角色：后提交者收到冲突提示，不静默覆盖。
- 项目列表在删除瞬间被刷新：以服务端结果为准，已删除条目不再出现，不显示已删除条目的详情。
- 邀请列表中的邀请已被兑换或过期：列表反映真实状态，不展示可操作的假按钮。
- 归档组织后仍停留在设置页的另一个标签页：提交被拒绝并引导离开该组织，去向同样遵循「下一个可用组织 → 引导状态」。
- 首页统计数字与列表页不一致（并发新建/删除项目时）：以各自查询时刻的数据为准，不缓存过期数字冒充实时。
- 用户会话过期时停在任意控制台页面：任何操作被拒绝并引导重新登录，不返回组织数据。
- 只读成员通过直接输入管理端点地址绕过界面：提交仍被拒绝，界面禁用不是唯一防线。
- 加载失败后用户点击「重试」：只重发当前页面的数据请求，不重复执行任何写操作；重试期间仍显示骨架屏。
- 会话失效与加载失败的区分：前者引导重新登录，后者留在页内重试，两者不得互相误判。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在用户登录后提供工作台控制台，包含首页、项目、成员、设置四个主页面，且始终处于某一个当前组织的上下文中。
- **FR-002**: 系统必须在引导状态（无可用组织）下展示创建组织与接受邀请的入口，不展示四个主页面，不静默创建组织。
- **FR-003**: 首页必须展示当前组织的概览：项目数、成员数、最近项目列表（固定 5 条，附「查看全部」入口跳转项目页）、待处理邀请数，以及「新建项目」「邀请成员」快捷入口；不引入图表、报表或跨组织聚合。
- **FR-004**: 项目页必须列出当前组织的全部项目，支持新建、打开、修改与删除；新建与修改必须拒绝空或纯空白名称；删除必须经过用户确认。
- **FR-005**: 成员页必须展示当前组织的成员名单（含角色与 owner 标记）与待处理邀请列表，并支持邀请、撤销邀请、修改成员角色、移除成员与转移所有权。创建邀请成功后必须通过弹窗展示可复制的邀请链接，明文 token 只出现一次。
- **FR-006**: 设置页必须包含「组织设置」（改名、归档）与「账号设置」（显示名、密码）两个分区；组织设置按角色权限展示，账号设置只对本人生效。
- **FR-007**: 控制台必须支持在多个可用组织之间切换当前组织；切换即记住——切换后该组织成为账号的默认组织（更新「上次使用的组织」），下次登录直接进入，无需单独的「设为默认」操作。
- **FR-008**: 切换或进入组织后，四个页面展示的数据必须全部限定在该组织内，不得出现跨组织数据（`FR-TEN-01` 的界面兑现）。
- **FR-009**: 无权访问的组织或数据必须返回「不存在或无权」的明确结果，不泄漏目标数据的存在性（`FR-TEN-03`）。
- **FR-010**: 所有写操作必须受角色权限约束：只读成员可查看但不可创建、修改、删除或管理成员；权限不足时入口不可用且服务端同样拒绝，界面禁用不是唯一防线。
- **FR-011**: 所有破坏性或不可逆操作（删除项目、移除成员、归档组织、撤销邀请、转移所有权）必须在执行前获得用户明确确认，并说明后果。
- **FR-012**: owner 的成员行不可被移除或改角色；所有权转移只允许转移给已是成员的人，并发转移只有一方成功（`FR-ORG-03`、`US-008` 的界面兑现）。
- **FR-013**: 已归档组织不得作为当前组织进入；组织归档后数据保留，写入被拒绝（`FR-ORG-02`、`EC-08`）。归档当前组织后，控制台必须自动切换到下一个可用组织，没有其他可用组织时进入引导状态。
- **FR-014**: 会话失效时，控制台的任何读写操作必须被拒绝并引导重新登录，不返回组织数据（spec 002 `FR-012` 的界面兑现）。
- **FR-015**: 空状态必须以明确的空状态与下一步入口呈现（无项目、无成员待办、无邀请），不得显示错误或虚构示例数据。
- **FR-016**: 系统必须在组织切换器旁提供「创建组织」入口；创建必须通过弹窗完成，弹窗内必须提供基于显示名或邮箱前缀的建议组织名称选项供直接选用，也允许自定义名称；创建成功后该组织自动成为当前组织。
- **FR-017**: 页面数据加载中必须显示骨架屏占位；加载失败时必须在页面内显示明确错误与「重试」入口，不清空已加载的既有数据，也不跳转登录（会话失效除外，此时按 `FR-014` 引导重新登录）。

### Key Entities *(include if feature involves data)*

- **组织（Organization）**: 控制台的上下文单位，本批次只消费其名称、状态与成员关系，不新增组织属性。
- **组织成员**: 成员页的数据来源，关键属性为角色与 owner 标记；owner 不是成员角色。
- **邀请**: 成员页待处理列表的数据来源，关键属性为目标邮箱、拟授予角色与状态；本批次只做列表、创建与撤销的界面，兑换规则见 `DM-INV-01`~`05`。
- **项目（Project）**: 项目页的数据来源，关键属性为名称与所属组织；本批次只做控制台层的列表与增删改，不涉及项目内部业务数据。
- **账号资料**: 设置页账号分区的数据来源，关键属性为显示名与密码；只对本人生效。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户从登录进入控制台到打开首页并看懂当前组织状态，中位耗时不超过 10 秒；首页关键数字（项目数、成员数）与实际数据不一致的页面比例为 0。
- **SC-002**: 从首页点击快捷入口到达项目创建或成员邀请入口，两步以内可达的入口比例为 100%。
- **SC-003**: 只读成员成功执行写操作的比例为 0（界面与服务端双重拦截）；其可正常查看页面的比例为 100%。
- **SC-004**: 跨组织数据泄漏的页面比例为 0：切换组织后仍展示上一组织数据的页面数为 0；按 ID 访问无权数据返回「不存在或无权」的比例 100%。
- **SC-005**: 破坏性操作未经确认即执行的比例为 0；确认后操作成功率不低于 99%，失败时均有明确提示。
- **SC-006**: 并发转移所有权的成功方数量恰好为 1，其余请求收到明确错误的比例 100%。
- **SC-007**: 已归档组织可被进入为当前组织的次数为 0；无可用组织的用户 100% 看到引导状态而非空白或报错页。
- **SC-008**: 常用操作（新建项目、邀请成员、修改成员角色）从控制台任意主页面出发，中位操作步数不超过 3 步。
- **SC-009**: 会话过期后的控制台操作 100% 被拒绝并引导重新登录，返回的组织业务数据记录数为 0。
- **SC-010**: 空组织、空项目列表、无邀请三种空状态均展示明确空状态与下一步入口，显示错误或示例数据的比例为 0。

## Assumptions

- 组织、成员、邀请、项目的服务端规则与端点已由 [endpoints.md](../../docs/architecture/api/endpoints.md) §2.2、§2.3 定值，本批次只做控制台界面与其验收，不新增服务端能力；若实现中发现缺口，回到契约文档修订而非在本批次另立规则。
- 「等等」按业界控制台惯例收敛为四个主页面：首页、项目、成员、设置；组织切换与引导状态作为横切能力纳入（2026-11-15 澄清）。仪表盘图表、审计日志查看、通知中心、跨组织聚合统计不在本批次内。
- 设置页包含账号本人资料分区（2026-11-15 澄清）；修改密码沿用既有账号端点与规则，本批次不重新定义密码策略。
- 首页只做当前组织概览（2026-11-15 澄清），不做跨组织聚合；组织切换即记住（切换后该组织成为默认组织，与 spec 002 `FR-014` 一致，2026-11-15 计划阶段修正）。
- 「最近项目」按最近更新时间排序，无更新记录时按创建时间；首页固定展示 5 条并提供「查看全部」跳转项目页（2026-11-15 澄清）。这是排序与展示约定，不是新的持久化事实。
- 项目删除的语义（级联范围、RESTRICT/CASCADE）以数据模型文档为准，本批次只负责确认提示与列表刷新，不重新定义删除规则。
- 控制台为登录后使用的内部工具，不做 SEO 与公开访问（`OOS-12`）；不引入实时推送，页面数据以进入页面与手动刷新时的查询结果为准。
- 本批次不引入缓存层、消息队列或新的数据存储（`OOS-09`、`OOS-14`）；统计数字由现有数据直接查询得出。
- 未定义的权限名与分页参数沿用 Phase 0 已定值的契约（C3、C4），本批次不新增权限名或分页约定。

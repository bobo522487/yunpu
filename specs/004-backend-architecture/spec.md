# Feature Specification: 后端架构收口与谱系核心数据落地

**Feature Branch**: `004-backend-architecture`

**Created**: 2026-11-24

**Status**: Draft

**Input**: User description: "根据《云谱（yunpu）后端架构改进方案》跑 specify 流程：收口运行时、焊死多租户隔离、落地谱系图核心数据结构、收拢后端边界与端到端类型契约、补齐工程门禁与验收。"

**基线与引用**: 本批次对齐仓库既有架构基线 [overview](../../docs/architecture/overview.md)、[stack](../../docs/architecture/stack.md) 与宪法 Article I–IX；输入方案见会话附件《yunpu 后端架构改进方案》。本规格只定义「本批次要交付什么、如何验收」，不复制完整技术选型表，也不重新定义组织/认证/工作台控制台已在 spec 002/003 交付的行为。

## 术语

- **单一运行时**：后端开发、迁移、测试与生产启动只允许一种受支持的服务端运行方式，禁止混用第二套启动器或迁移执行器。
- **租户事务入口**：业务写读必须经过「已绑定当前组织」的唯一事务通道；禁止业务模块直接持有未绑定租户上下文的裸数据库连接。
- **FORCE RLS 护栏**：所有业务表必须同时开启行级安全与强制行级安全；缺失即视为缺陷，由自动化检查阻断合并。
- **人物（Person）**：一份谱项目中的人物节点。
- **关系边（Relation Edge）**：人物之间的亲属关系事实（血亲父母、收养父母、配偶）；是谱系关系的唯一事实源。
- **谱系投影（Lineage Projection）**：由关系事实派生的加速层（如世代位置），永不单独充当真相源，必须与关系边同事务刷新。
- **受控子图**：按根人物与上下深度、数量上限返回的局部人物与边集合，附带「是否还有更多祖先/后代」的折叠提示。
- **统一错误信封**：所有非成功 API 响应使用同一结构化错误形状（错误码、可读消息、请求标识、可选细节）。
- **端到端类型契约**：后端路由形状作为前端可消费的类型真相源，避免手工同步 DTO。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运维与开发者在单一运行时上启动、迁移与测试 (Priority: P1)

一位后端开发者或运维在本机与 CI 中，用同一套受支持的运行方式启动 API、执行数据库迁移并跑完全部测试。仓库中不再残留第二套启动/迁移命令路径；健康检查与就绪探针可正常通过。

**Why this priority**: 运行时混搭是当前最直接的交付阻塞——同一仓库若无法用统一方式启动与验证，后续隔离护栏与谱系数据都无法稳定落地。

**Independent Test**: 在干净环境按文档用唯一受支持方式启动服务、执行迁移并跑测试套件；全文检索确认无第二套运行时命令残留；就绪接口返回成功。

**Acceptance Scenarios**:

1. **Given** 已配置合法环境变量与可用数据库，**When** 用受支持的唯一方式启动 API，**Then** 服务监听成功，就绪检查返回可用。
2. **Given** 存在待应用迁移，**When** 用受支持的唯一方式执行迁移，**Then** 迁移完成且无第二套迁移命令被调用。
3. **Given** 测试环境已就绪，**When** 执行统一测试入口，**Then** 全部测试通过（含既有基线用例）。
4. **Given** 仓库全量脚本与文档，**When** 检索第二套运行时命令残留，**Then** 业务脚本中无命中（白名单系统说明除外）。
5. **Given** 服务收到关闭信号，**When** 执行优雅关闭，**Then** 停止接收新请求、排空在途请求后再释放数据库连接，进程正常退出。

### User Story 2 - 租户隔离在代码入口与自动化检查中被强制执行 (Priority: P1)

一位安全相关干系人要求：业务代码无法绕过租户上下文访问数据库；任何新增业务表若未强制开启行级安全，合并流水线必须失败。跨组织读写在集成验证中只能得到空结果或不暴露资源存在的失败响应。

**Why this priority**: 宪法要求「规则要有执行者」与「隔离靠数据库」。文档级 RLS 承诺若无事务入口与 CI 断言，仍是愿望而非护栏。

**Independent Test**: 业务模块导入检查阻断裸数据库句柄；迁移后结构断言失败可复现；跨租户读写集成用例 100% 按预期拒绝或空返回。

**Acceptance Scenarios**:

1. **Given** 业务服务需要访问租户数据，**When** 通过唯一租户事务入口执行，**Then** 事务内已绑定当前组织上下文，且事务结束后该绑定不泄漏到连接池后续请求。
2. **Given** 某业务模块尝试直接使用未绑定租户的裸数据库句柄，**When** 静态依赖检查运行，**Then** 检查失败并指出违规导入。
3. **Given** 某业务表未开启强制行级安全，**When** 结构断言测试运行，**Then** 测试失败并列出表名。
4. **Given** 用户 A 属于组织甲，**When** 尝试读取或修改组织乙的人物/项目数据，**Then** 对外表现为空或不可发现失败（不泄露资源存在），审计侧可区分真实越权。
5. **Given** 幂等读或带幂等键的写遇到可重试瞬态故障，**When** 租户事务入口处理，**Then** 最多有限次退避重试后成功或明确失败；唯一键冲突与版本冲突直接冲突失败且不重试。

### User Story 3 - 修谱者在项目中维护人物与亲属关系且不会形成血缘环 (Priority: P1)

一位修谱主事人在某个项目中创建人物、建立父母/收养/配偶关系。系统拒绝会形成血缘环的父母类关系写入，并给出明确冲突反馈；合法关系持久保存后可再次读取一致。

**Why this priority**: 人物与关系边是谱系产品的核心事实；没有它们，工作台与后续视图没有可编辑的业务重心。防环是数据完整性的硬约束。

**Independent Test**: 在真实数据库中创建人物与边；构造会导致环的父母边并确认被拒绝；确认配偶与合法父母边可写入；失败事务不留下半成品。

**Acceptance Scenarios**:

1. **Given** 用户对某项目有编辑权限，**When** 创建人物（显示名等必填合法），**Then** 人物属于该组织与项目，并可再次读出。
2. **Given** 两个人物同属一项目，**When** 建立合法的血亲父母、收养父母或配偶关系，**Then** 关系边保存成功，同向同类型不重复。
3. **Given** 建立父母类关系会形成环（例如把后代设为自己的祖先），**When** 提交写入，**Then** 请求被拒绝，返回明确的环检测冲突，不写入该边。
4. **Given** 用户尝试把人物连到自己，**When** 提交，**Then** 被约束拒绝。
5. **Given** 写入过程中后续步骤失败，**When** 事务结束，**Then** 人物/边/投影均完整回滚，不出现部分提交。
6. **Given** 其他组织的用户，**When** 尝试读写本项目人物或边，**Then** 无法成功访问（同 US2 隔离语义）。

---

### User Story 4 - 前端按视口拉取受控谱系子图而非整谱倾倒 (Priority: P2)

一位正在浏览家谱图的用户（经前端）请求以某人物为根、限定上下代数与条数上限的子图。系统返回该视口所需的人物与边，并告知是否还有未展开的祖先或后代；默认不返回整个项目的全量人物与边。

**Why this priority**: 千人谱系若一次倾倒会拖垮端到端体验；受控子图是核心数据可交互展示的前提，但依赖 US3 的人物与边已存在。

**Independent Test**: 在约数千人规模的模拟谱上，按默认深度与上限请求子图，确认结果规模受控、折叠提示正确，且跨项目/跨组织不可读。

**Acceptance Scenarios**:

1. **Given** 项目中已有足够深的血缘链，**When** 以根人物、默认向上/向下深度与数量上限请求子图，**Then** 返回集合不超过上限，并正确设置是否还有更多祖先/后代。
2. **Given** 根人物不存在或不属于该项目，**When** 请求子图，**Then** 按统一错误/不可发现语义处理，不泄露其他租户数据。
3. **Given** 调用方未传深度或上限，**When** 请求，**Then** 使用安全默认值（向上 2、向下 4、上限 300），绝不默认「整项目」。
4. **Given** 约 5,000 人规模的模拟家谱，**When** 重复请求典型视口子图，**Then** 用户可感知响应迅速（见成功标准 SC-004）。

### User Story 5 - 后端边界清晰且前端可消费稳定 API 契约 (Priority: P2)

一位前端开发者对接后端时，只面对清晰的版本化 API 与可推导的路由类型契约；认证相关能力只有一处模块入口；错误响应形状一致；越权对外不暴露「存在但禁止」。

**Why this priority**: 目录重复与松散类型契约会放大联调成本与安全误用；在运行时与核心数据收口后，契约稳定才能支撑工作台与谱图前端。

**Independent Test**: 确认认证对外入口唯一；抽样若干错误路径均为统一信封；前端工程可仅依赖导出的应用路由类型完成编译期对接（无手工 DTO 双份维护）。

**Acceptance Scenarios**:

1. **Given** 仓库后端源码，**When** 定位认证路由、会话读取与鉴权守卫，**Then** 均从单一认证模块对外暴露，不存在并行的第二套认证目录对外出口。
2. **Given** 任意业务 API 返回非成功状态，**When** 客户端解析响应体，**Then** 均为统一错误信封，并带有请求标识便于排障。
3. **Given** 用户越权访问他人资源，**When** 查看对外响应，**Then** 表现为不可发现（如 404 语义），不返回「禁止但存在」的区分信息。
4. **Given** 前端需要调用版本化 API，**When** 使用后端导出的端到端类型契约，**Then** 路由路径与成功/失败形状可在编译期对齐，无需维护第二份手写 DTO 清单。

---

### User Story 6 - 工程门禁阻止错误依赖方向与假事务测试 (Priority: P3)

一位维护者提交代码时，静态检查阻止共享层依赖业务模块、阻止模块间偷用对方内部仓储/路由、阻止业务层直连裸连接池；集成测试在真实数据库上验证跨租户、防环与回滚，禁止用假事务冒充数据库行为。

**Why this priority**: 门禁巩固前序故事的成果，避免回归；本身不单独交付新业务能力，故优先级靠后。

**Independent Test**: 故意引入违规导入使静态检查失败；集成测试套件在独立测试库上绿；确认测试中无「假事务」替身替代真实提交/回滚语义。

**Acceptance Scenarios**:

1. **Given** 共享包尝试导入业务模块，**When** 静态检查，**Then** 失败。
2. **Given** 模块 A 直接导入模块 B 的内部仓储或路由文件，**When** 静态检查，**Then** 失败。
3. **Given** 集成测试覆盖跨租户、防环、事务回滚，**When** 在真实测试库执行，**Then** 三类用例全部通过且不依赖假事务。

---

### Edge Cases

- 连接池复用连接时，上一事务的租户绑定不得泄漏到下一请求。
- 父母类边与配偶边并存时，防环只约束父母类路径，配偶不参与祖先环判定。
- 子图在深度未用尽但已达条数上限时，必须仍返回折叠提示，避免调用方误以为已到尽头。
- 迁移白名单仅允许明确的系统/认证例外表；新增业务表默认计入 FORCE RLS 断言。
- 并发两人同时编辑同一人物版本时，后提交者收到明确冲突，不静默覆盖。
- 服务关闭过程中到达的新请求被拒绝或不再接受，不得写入半关闭状态的数据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 仅支持单一服务端运行方式完成 API 启动、数据库迁移与测试执行；仓库业务脚本中不得保留第二套运行时命令路径。
- **FR-002**: 系统 MUST 在关闭信号下执行优雅停机：停止接收 → 排空在途 → 释放数据连接后退出。
- **FR-003**: 业务模块 MUST 只能通过唯一租户事务入口访问租户数据；不得导出或使用未绑定组织上下文的裸数据库句柄。
- **FR-004**: 租户事务入口 MUST 在事务内绑定当前组织，并保证事务结束后绑定不泄漏。
- **FR-005**: 系统 MUST 对可重试瞬态故障提供有限次退避重试；对唯一键冲突与乐观锁版本冲突 MUST 直接返回冲突且不重试。
- **FR-006**: 自动化结构检查 MUST 在每次迁移后验证全部应受保护的业务表已开启强制行级安全；任何违规表导致检查失败。
- **FR-007**: 系统 MUST 支持在项目内创建、读取与更新人物节点，人物归属组织与项目边界清晰。
- **FR-008**: 系统 MUST 支持在同项目人物之间创建血亲父母、收养父母与配偶三类关系边，并拒绝自环与同向同类型重复边。
- **FR-009**: 系统 MUST 在写入或修改父母类关系时检测血缘环；检测到环时拒绝写入并返回明确冲突。
- **FR-010**: 关系边是亲属关系的唯一事实源；任何加速用的谱系投影 MUST 与写路径同事务刷新，且不得单独作为真相源。
- **FR-011**: 系统 MUST 提供受控子图查询：按项目、根人物、上下深度与数量上限返回局部人物与边，并包含是否还有更多祖先/后代的提示；默认参数必须是安全有限值，不得默认返回整项目。
- **FR-012**: 认证相关对外能力（路由、会话读取、鉴权守卫）MUST 仅从一个认证模块出口暴露。
- **FR-013**: 所有非成功 API 响应 MUST 使用统一错误信封（错误码、消息、请求标识、可选细节）。
- **FR-014**: 权限越权对外 MUST 使用不可发现语义；真实禁止原因仅留在内部审计。
- **FR-015**: 后端 MUST 导出可供前端消费的端到端路由类型契约，作为 API 形状的单一真相源。
- **FR-016**: 静态依赖检查 MUST 阻断：共享层→业务模块、跨模块内部仓储/路由、业务模块→裸连接池等违规方向。
- **FR-017**: 跨租户隔离、血缘防环、事务失败回滚三类场景 MUST 在真实数据库集成测试中覆盖，且不得用假事务替代。
- **FR-018**: 数据库结构变更 MUST 以可审计的迁移脚本提交版本库；禁止依赖生产环境「推送式」改库或应用启动时自动迁移作为发布手段。

### Key Entities

- **人物（Person）**：谱项目中的个体节点；关键属性包括归属组织/项目、显示名、性别、生卒年或在世标记、乐观锁版本。
- **关系边（Relation Edge）**：两人之间的亲属事实；含边类型（血亲父母 / 收养父母 / 配偶）与可选元数据；同一项目内同向同类型唯一。
- **谱系投影（Lineage Projection）**：由关系边派生的位置/世代加速数据；随写路径刷新；查询可使用但冲突时以关系边为准。
- **组织与项目**：既有租户与谱数据边界（见既有规格）；本批次人物与边挂载其上，不重新定义其生命周期。
- **租户事务上下文**：一次业务操作绑定的当前组织标识及其可见性；由唯一入口设置，事务结束清除。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在干净环境中，使用唯一受支持方式可在 5 分钟内完成「启动服务 → 就绪检查通过 → 跑通迁移 → 测试入口全绿」。
- **SC-002**: 仓库业务脚本与启动文档中，第二套运行时命令残留检索命中数为 0。
- **SC-003**: 跨租户越权读写的自动化用例通过率为 100%；故意去掉强制行级安全的表会使结构断言失败。
- **SC-004**: 在约 5,000 人的模拟家谱上，典型受控子图查询的 P95 响应时间小于 200ms（在约定的测试硬件与数据库环境下测量）。
- **SC-005**: 构造环的父母类关系写入被拒绝率 100%，且失败后相关表无脏数据残留。
- **SC-006**: 前端对接版本化 API 时，无需维护第二份手写接口清单即可保持路径与错误形状编译期一致（抽样子路由全覆盖）。
- **SC-007**: 静态依赖方向门禁对已知违规样例的检出率为 100%。

## Assumptions

- 本批次范围覆盖后端 API、数据库结构与工程门禁；工作台控制台 UI（spec 003）与登录注册产品流程（spec 002）行为不在本批次重新设计。
- 「单一运行时」落地目标与输入方案一致：服务端统一到当前 LTS Node 线路与 pnpm 工作流；具体版本号以仓库 `engines` 与锁文件为准，本规格只约束「唯一」与可验证启动/迁移/测试路径。
- 双数据库角色（业务角色与认证运行角色）及 RLS 租户隔离策略延续既有架构，不改为单角色或应用层 WHERE 替代。
- 谱系投影作为派生加速层予以保留，以满足受控子图性能目标；它不是第二份关系事实。若与「可推导数据尽量不落库」原则在计划阶段冲突，须在 plan 的复杂度登记中写明取舍。
- 受控子图默认参数：向上深度 2、向下深度 4、条数上限 300。
- 服务端渲染的登录/注册页面将随前端 SPA 接管而逐步下线；本批次以保证 `/api` 版本化接口与静态回退职责清晰为验收重点，完整删除服务端鉴权页可列为收尾任务而非阻塞 SC。

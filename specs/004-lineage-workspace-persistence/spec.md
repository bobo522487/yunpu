# 004: 谱系工作区后端持久化与演示数据初始化

> 本文件只描述业务行为、规则与验收契约，不包含技术实现细节。

## 1. Overview

本变更将家族项目下的平铺目录分组（`Folder`）、世系谱表（`Lineage`）、前端界面展示的全部人物世系信息（`Person`、`PersonName`、`PersonRelation`、`PersonEvent`）以及家族项目元数据中的始迁祖（`Project.ancestor`）统一纳入后端持久化，以服务端为唯一事实来源；同时彻底移除前端 Mock 与本地业务实体持久化，并为每一位新注册用户在个人默认组织内自动初始化一套可编辑、可删除的家族范例演示项目。

### 非目标（Out of Scope）

- 谱文（`Article`）与谱书（`Book`）的后端持久化和编排服务不在本次交付范围内（将在后续功能中复用同一套 `Folder` 分组机制接入）。
- 谱书成书导出与离线备份迁移工具不在本次交付范围内（浏览器端原有未同步的本地演示数据直接弃用）。

---

## 2. User Stories

- **US-01**：作为组织成员，我希望在家族项目内使用平铺文件夹（`Folder`）对多张谱系图进行分组与排序，以便按支派或参考类别清晰组织目录，且删除文件夹时不会误删其中的谱系图。
- **US-02**：作为组织编辑者，我希望创建、编辑、切换与删除多张独立的谱系图（`Lineage`），并在新建谱系图填写始祖时自动生成第一世始祖人物节点，以便即刻开展世系录入。
- **US-03**：作为组织编辑者，我希望在新建或修改家族项目时保存「始迁祖」（`ancestor`），且新建项目填写始迁祖时同步生成首张谱系图与第一世始迁祖节点，以便项目档案与世系画布开局一致。
- **US-04**：作为组织编辑者，我希望前端人物详情面板、新增亲属弹窗与时间线所展示和编辑的完整资料（姓名、拼音、性别、在世/已故、结构化生卒与葬地、别名、全部血缘/拟制亲子与配偶关系、生平事件、传记与备注）都能实时持久化到服务端，并具备并发版本冲突保护。
- **US-05**：作为新注册用户，我希望首次注册进入个人默认组织时即看到一套完整的示范家族项目（含分组、谱系图、多代人物与关系/别名/事件），以便快速了解产品能力，同时能够自由修改或物理删除该示范项目。
- **US-06**：作为协作成员，我希望所有谱系读写都直接基于真实账号权限和服务端数据运行，不再因本地缓存或离线 Mock 造成假成功或跨账号残留。

## 3. Functional Requirements

### FR-001：家族项目平铺分组（`Folder`）管理
- 同一 `Project` 内支持创建、查询、重命名与调整分组顺序（`seq >= 0`），分组为平铺一级结构，不支持文件夹嵌套文件夹。
- 同一 `Project` 内分组名称不得为空白，且必须唯一（重复名称应被明确拒绝）。
- 只有 `Folder` 所挂载的顶层内容根（本次为 `Lineage`，后续包含谱文与谱书）可关联至某个 `Folder` 或处于未分组状态。
- 物理删除 `Folder` 时，仅解除其与下属内容根的关联（下属 `Lineage` 回到未分组根层级），不得连带删除内容本身。
- 权限：任意组织成员可读取；至少需要 `editor` 角色方可执行创建、修改与删除。

### FR-002：谱系图（`Lineage`）管理与并发控制
- 同一 `Project` 内支持创建、查询、编辑、重排序、移入/移出 `Folder` 以及物理删除 `Lineage`。
- `Lineage` 包含名称（必填非空）、主姓氏、堂号、始祖名称、所在地区（支持省市区县结构化地点或原始地名文本）、所属 `Folder`（可空）、排序序号（`seq >= 0`）与乐观锁版本号（`version`）。
- 创建 `Lineage` 时若提供始祖名称，系统在同一操作内自动创建该谱系图下的第一世始祖 `Person`；若指定了 `Folder`，该 `Folder` 必须属于同一 `Project`。
- 更新 `Lineage` 元数据或归属分组时必须校验 `version`；版本落后时拒绝覆盖并提示冲突。
- 物理删除 `Lineage` 时，同步物理删除其下属的所有 `Person`、`PersonName`、`PersonRelation`、`PersonEvent` 及对应世系投影。
- 权限：任意组织成员可读取；至少需要 `editor` 角色方可执行创建、修改与删除。

### FR-003：`Project.ancestor` 持久化与开谱联动初始化
- `Project` 新增可选字段 `ancestor`（始迁祖，非空时不得为纯空白），支持在创建与更新项目时持久化并返回。
- 新建 `Project` 时若传入非空 `ancestor`，系统在同一原子操作内自动为该项目创建一张初始 `Lineage`（继承项目名称/姓氏/堂号/地区/`ancestor`）及对应的第一世始迁祖 `Person`。
- 修改已有 `Project` 的 `ancestor` 仅更新项目档案元数据，不自动改写或新建已存在的 `Lineage` 与人物节点。

### FR-004：人物（`Person`）全量界面字段持久化与乐观锁
- 每位 `Person` 必须归属于同一 `Project` 下的某一张 `Lineage`。
- 人物支持并持久化前端界面展示与编辑的全部核心属性：
  - **身份与姓名**：姓氏、名字、姓名拼音（姓拼音/名拼音/后缀）、性别（`male`/`female`/`unknown`/`other`）、在世状态（`living`/`deceased`）；
  - **生卒与葬地**：公历生卒年份、结构化出生信息（历法日期、出生地点、摘要）、结构化死亡信息（历法死亡日期、死亡地点、葬期、葬地、死因、手动享年、摘要）；
  - **谱系编排**：字辈字、称谓标题（如「始祖」）、同辈/配偶展示次序（`>= 0`）；
  - **行传与档案**：传记简介、备注、肖像引用（若接入媒体存储则存受保护引用，禁止将大体积原始图片数据直接内联入业务文本）。
- 校验规则：在世人物不得携带死亡年份或死亡日期/葬地结论（若录入死亡年份或死亡日期则状态应为已故，且卒年不得早于生年）；每次更新校验整数 `version`，版本不匹配拒绝写入。

### FR-005：人物名号与别名（`PersonName`）管理
- 在现有 `PersonName` 语义基础上，支持为人物新增、修改、删除多种名号记录（本名 `formal`、字 `courtesy`、号 `art`、乳名 `milk`、谱名 `genealogy`、谥号 `posthumous`、其他 `other`），并扩展展示层字段：别名字体（如「曾用名」展示标签）、别名姓氏与别名拼音。
- 保留同一 `Person` 在同一 `Project` 内至多一条主名（`isPrimary`）及同类型同名唯一的约束。

### FR-006：人物关系（`PersonRelation`）全集与扩展标签管理
- 开放全部 7 种人物关系类型的写入与维护：亲生父母（`biological_parent`）、养父母（`adoptive_parent`）、继嗣/过继（`ritual_heir`）、继父母（`step_parent`）、抚养父母（`foster_parent`）、配偶（`spouse`）、伴侣（`partner`）。
- 支持读写关系扩展属性：源端角色标签（`fromRoleLabel`）、目标端角色标签（`toRoleLabel`，如「生子」「过继」「续弦」）、排序序号（`sortOrder >= 0`）与关系备注（`note`）。
- 不变量：禁止自环；禁止跨 `Project` 或跨 `Lineage` 建立人物关系；对称关系（`spouse`/`partner`）保持规范序存储；亲子关系继续受父母数量上限与环检测约束。

### FR-007：人物生平事件（`PersonEvent`）管理
- 支持为人物创建、查询、编辑与物理删除生平时间线事件（类型覆盖：`birth`、`education`、`career`、`marriage`、`residence`、`death`、`other`）。
- 每条事件包含结构化历法日期、结构化地点、事件描述与顺序号（`>= 0`）。
- 人物物理删除时，其下所有生平事件随同物理清除。

### FR-008：谱系图全量数据加载与多视图支持
- 支持按指定 `Lineage` 一次性读取该谱系图元数据及其下属 `Person`（含名号与生平事件）、`PersonRelation` 与主脉世系投影（`LineageProjection`），同时保留既有按根人物受控子图查询能力。
- 前端树形图、行传视图、网格视图与表格视图均直接由服务端返回数据派生渲染；新增亲属、删除人物或修改亲子/配偶关系后以服务端返回结果为准更新界面。

### FR-009：新用户范例家族演示数据自动初始化
- 新用户在无有效邀请的情况下完成注册并建立个人默认 `Organization` 时，系统自动在该组织内初始化 1 个完整的范例家族 `Project`（包含 1 个 `Folder`、1 张 `Lineage`、三代以上示范人物、配偶/亲子关系、别名与生平事件）。
- 该范例项目及其下属文件夹、谱系图、人物均是该组织内真实持久化的数据，拥有正常版本号与权限控制，用户可自由编辑、扩充或物理删除。
- 用户通过有效邀请链接注册并直接加入他人 `Organization` 时，不得向被加入的他人组织写入范例项目；若邀请失败回退为个人默认组织时，则按个人默认组织规则初始化范例项目。

### FR-010：前端彻底去 Mock 与去本地业务持久化
- 移除前端所有本地 Mock 运行分支（含演示账号、Mock Auth、Mock Console、直连 Mock 传输切换与登录页 Mock 提示）。
- 移除浏览器本地存储中的谱系业务实体持久化与「导入演示数据」按钮；前端仅允许在本地保留纯界面临时交互态（如当前选中的谱系图 ID、当前选中的人物 ID、视图模式、抽屉宽度）。
- 所有登录状态、组织、项目、文件夹、谱系图、人物、名号、关系与事件请求统一走真实 API，网络或业务错误直接对用户显式展示。

## 4. Business Rules

- **租户隔离**：所有新增与扩展实体（`Folder`、`Lineage`、`PersonEvent` 等）均归属特定 `Organization` 与 `Project`，严格遵守组织成员隔离；非成员访问一律返回「不存在或无权」（`404`）。
- **归档只读**：处于 `archived` 状态的 `Organization` 禁止对其下任何 `Project`、`Folder`、`Lineage`、`Person`、`PersonName`、`PersonRelation`、`PersonEvent` 执行写操作（返回 `409`）。
- **删除即物理删除**：除 `Folder` 删除对其下 `Lineage` 采取「解绑保留」外，删除 `Project`、`Lineage`、`Person`、`PersonName`、`PersonRelation`、`PersonEvent` 均为物理删除；物理删除 `Project` 时级联清理其下所有子资源。
- **单一事实来源**：前端不得在本地自行推算覆盖服务端版本号；遇到 `409 VERSION_CONFLICT` 应提示用户刷新后重试。

---

## 5. Exception Handling

- 跨组织访问、目标 `Project`/`Folder`/`Lineage`/`Person`/`Relation`/`Event` 不存在或不属于同一父容器：返回 `404 NOT_FOUND`。
- 成员权限不足（如 `viewer` 尝试写 `Folder`/`Lineage`/`Person`/`Event`，或非 `admin` 尝试删除 `Project`）：返回 `403 FORBIDDEN`。
- 归档组织写入、`Folder` 同名冲突、`PersonName` 重复、谱系环路（`CYCLE_DETECTED`）、父母上限（`PARENT_LIMIT`）、跨谱系图连边、`version` 过期（`VERSION_CONFLICT`）：返回 `409` 及对应明确错误码。
- 非法输入格式（空白名称、负数序号、非法日期/事件类型、在世人物填死年、自环关系）：返回 `400 VALIDATION` 与 `fieldErrors`。
- 未登录或会话失效：返回 `401 UNAUTHORIZED`。

## 6. Acceptance Criteria

- [ ] **AC-001**（对应 `FR-001`）：在项目内创建、重命名、重排平铺 `Folder`，将 `Lineage` 移入/移出 `Folder`；删除非空 `Folder` 后，原下属 `Lineage` 仍保留且 `folderId` 置空；同项目创建重名 `Folder` 返回 `409 CONFLICT`。
- [ ] **AC-002**（对应 `FR-002`）：创建带 `progenitor` 的 `Lineage` 自动生成第一世始祖 `Person`；使用过期 `version` 更新 `Lineage` 返回 `409 VERSION_CONFLICT`；删除 `Lineage` 同步清除其下人物、关系与事件，不影响同项目其他 `Lineage`。
- [ ] **AC-003**（对应 `FR-003`）：创建项目传入 `ancestor` 后，项目返回携带 `ancestor` 且自动存在首张 `Lineage` 与始迁祖节点；更新项目 `ancestor` 携带整数 `version` 成功递增版本号并持久保存。
- [ ] **AC-004**（对应 `FR-004`）：前端修改人物姓/名/拼音、性别、在世/已故、结构化出生/死亡/葬期葬地、传记与备注并刷新页面后，服务端数据与界面展示完全一致；过期 `version` 更新返回 `409 VERSION_CONFLICT`。
- [ ] **AC-005**（对应 `FR-005`）：在人物抽屉中新增、编辑、删除字/号/谱名/曾用名及对应拼音后持久保存；同类型同值重复写入返回 `409 CONFLICT`。
- [ ] **AC-006**（对应 `FR-006`）：创建全部 7 类人物关系及角色标签/排序/备注均成功落库并可在刷新后还原；试图跨 `Lineage` 连边、自环或制造环路均被拒绝。
- [ ] **AC-007**（对应 `FR-007`）：新增、编辑、删除人物生平时间线事件（含结构化历法日期与地点）后刷新一致；删除该人物时事件级联清除。
- [ ] **AC-008**（对应 `FR-008`）：切换项目内不同 `Lineage` 时仅加载对应谱系图的人物与关系并在树/行传/表格视图正确呈现。
- [ ] **AC-009**（对应 `FR-009`）：新用户普通注册完成后，个人默认组织自动包含 1 个可编辑与可物理删除的范例家族项目（含分组、谱系图与多代人物）；受邀注册加入他人组织时不向目标组织写入范例项目。
- [ ] **AC-010**（对应 `FR-010`）：代码中不再存在 Mock Auth / Mock Console / 离线直连 Mock 逻辑与本地谱系实体持久化；`viewer` 越权或跨组织访问均被真实后端拦截并正确反馈。

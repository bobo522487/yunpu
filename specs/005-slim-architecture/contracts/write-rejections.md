# Contract: 保存被拒绝时调用方看到什么

合法的登录、组织、工作台和谱系编辑成功路径不变。下面只规定以前靠服务层记得检查、现在必须由存储拒绝的情况。调用方都得到明确失败，存储保持拒绝前的内容。

## 人物年份

- **条件**: `death_year` 有值且 `is_living` 为真，或 `death_year < birth_year`。
- **存储**: CHECK 失败，SQLSTATE `23514`，约束名 `ck_person_life_years`。
- **调用方**: `VALIDATION` / 400，消息说明年份与在世状态不一致。

## 父母边超过两条

- **条件**: 同一项目、同一子女、同一 `biological_parent` 或同一 `adoptive_parent` 将变成第 3 条。直接插入也算，不经过预检查。
- **存储**: 触发器抛出 SQLSTATE `GX011`。
- **调用方**: `PARENT_LIMIT` / 409，消息仍是「同类型父母边已达上限」。
- **不变**: `ritual_heir` 不使用这个上限。配偶冲突与祖先环仍是现有的 `CONFLICT` 与 `CYCLE_DETECTED`。

## 已归档组织上的写入

- **条件**: 组织不是 `active` 时，向已落地的项目、人物、人名、关系、投影、成员或邀请做新增、修改或删除。
- **存储**: 触发器抛出 SQLSTATE `GX012`。
- **调用方**: `CONFLICT` / 409，消息仍是「组织已归档，无法写入」。
- **允许**: 把仍为 `active` 的组织更新为 `archived`。

## 角色不够与非成员

- **成员但达不到该表要求的角色**: 行级写入策略拒绝，SQLSTATE `42501`。访问函数把它变成今天的无权结果：`FORBIDDEN` / 403。
- **非成员**: 仍然看不到行，结果仍是「不存在」（人物、项目或组织的现有 not-found 错误），不能改成 403。
- **修改所有者角色**: 仍是 `CONFLICT` / 409，「不能修改所有者角色」。
- **本人退出、本人更新 `last_used_at`**: 仍然成功。本人若改角色或其他成员列，被触发器拒绝。

## 直接连接

业务模块里的代码不能拿连接池自行查询租户表。测试用绕过服务、但走租户事务的 SQL 覆盖以上拒绝，证明拒绝不依赖某个服务函数被调用到。

# Quickstart: 验收把权威还给行为本身

前提：本机或 CI 能连测试用的 PostgreSQL 18，依赖已安装。命令在仓库根目录执行。下面每条都是验收场景，不是实现代码。

## 1. 现行说明只剩两类

实现完成后：

- `docs/boundaries.md` 存在，并且只写健康检查、认证库、迁移命令这三类入口例外。
- `docs/decisions/` 至少包含原有的 PG 18 决策和所有者外键索引决策。
- `docs/README.md`、`docs/requirements/`、`docs/architecture/`、`docs/verification/`、`docs/superpowers/` 不存在。
- `.github/workflows/verify.yml` 与 `docs.yml` 不再调用 `scripts/check-docs.sh`。
- `scripts/check-docs.sh` 不存在。

## 2. 存储会拒绝非法组合

针对测试库，在租户事务里直接插入，不调用服务层的预检查：

- 第三条血亲父母边或第三条收养父母边被拒绝，调用方得到 `PARENT_LIMIT`。
- `is_living = true` 且填写了死亡年被拒绝，调用方得到 `VALIDATION`。
- 组织归档后，再插入人物被拒绝，调用方得到「组织已归档，无法写入」。
- 拒绝之后，原先的行还在，没有半条新边。

合法的创建人物、创建两条父母边、归档组织，仍按原来的成功结果完成。

## 3. 角色的可见结果不变

- 非成员写入人物：仍是不存在，不是无权。
- 成员但只是 viewer：写入人物被拒绝，结果是无权。
- editor 创建人物仍然成功。
- admin 删除项目仍然成功；editor 删除项目仍然被拒绝。
- 成员更新自己的 `last_used_at` 仍然成功；成员改自己的角色被拒绝。

## 4. 租户连接不会串

- 业务模块源码不能导入连接池或 `createDb`（lint 失败即未通过）。
- 同一条物理连接完成一次租户事务后，下一次不设置 `app.user_id` 的查询看不到上一租户的行。
- 健康检查不查询租户表。

## 5. 名单与树的等待时间

在一个项目中准备 10,000 位人物和把他们连成树所需的父母边。另准备第二个项目并把它的数据量再加倍。

- 第一个项目的人物列表与谱系子图各自在 2 秒内返回。
- 第二个项目加倍之后，再测第一次的列表与子图，耗时增幅都不超过 10%。
- 合法响应的字段与本特性之前一致。

超过预算时查看该查询的执行计划，用来判断是不是租户条件没有用上索引。计划文本不写回 `docs/`。

## 6. 改一处就能被接受

抽查三次变更的评审条件：

- 加一条 CHECK：只改迁移、Drizzle schema 和对应测试。
- 调整一个失败码的状态：只改 `ERROR_STATUS` 与映射测试。
- 调整一个路由字段：只改该路由的类型定义。

三次都不修改编号索引或追溯矩阵。合并不依赖文档校验、两次治理检查或复杂度例外账本。
